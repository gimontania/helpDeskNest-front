| 17-nov | US-01-Login | #1 | Inicio de sesión con persistencia en el frontend. Formulario con react-hook-form y zod: si el correo o la contraseña son inválidos no se envía ninguna petición. Las credenciales válidas llaman a POST /auth/login, guardan el token y abren la vista autorizada según el rol. Un 401 muestra un mensaje genérico, sin indicar si falló el correo o la contraseña. La sesión se restaura al recargar leyendo y validando el JWT (rol, correo y expiración). Si el token es inválido o está vencido, se borra. Cerrar sesión limpia el store y el token. api.ts adjunta Authorization: Bearer a cada petición. Un 401 con sesión activa cierra la sesión automáticamente |
